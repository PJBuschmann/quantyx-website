# Quantyx Website — Full Build Prompt

## Overview

Build a complete, multi-page professional website for **Quantyx Advisors**, an independent firm specializing in Risk Management and Valuation Services for Alternative Investments (Private Markets). The firm was founded in 2009 and has offices in Milan, Italy and Luxembourg.

The website must convey credibility, technical sophistication, and institutional-grade expertise. The tone is professional, precise, and confident — targeting institutional clients (AIFMs, GPs, LPs, ManCos) in the European private markets ecosystem.

---

## Brand & Design Direction

- **Primary color:** Deep navy blue (`#0A1628` or similar)
- **Accent color:** Electric blue / teal (`#0057FF` or `#0082C8`)
- **Secondary:** Clean white, light grey (`#F4F6F9`)
- **Typography:** Modern, clean sans-serif (e.g., Inter, DM Sans, or similar). Use weight contrast (light body, bold headings) to create hierarchy.
- **Style:** Minimal, data-driven, institutional. Think Bloomberg terminal meets McKinsey — not flashy, but precise and authoritative.
- **Imagery:** Abstract financial/data visuals, network graphs, geometric patterns. No stock photography of people shaking hands.
- **Navigation:** Fixed top navbar with: `Risk Management | Valuation | News | Careers | About Us` + a `Contact Us` CTA button (right-aligned).

## Tone & Copy Guidelines

- Institutional and precise. Never casual.
- Use active voice: *"We deliver…"*, *"We ensure…"*, *"We support…"*
- Avoid buzzwords like "synergy", "ecosystem", "unlock". Prefer: *independent, rigorous, transparent, regulatory-compliant, tailored.*
- All content should reinforce the message: **Quantyx is a trusted, independent, technically excellent partner for institutional investors operating in private markets.**

## Framework & Architecture

- **Framework:** Next.js (App Router)
- **Styling:** Tailwind CSS
- **Language:** TypeScript
- **Routing:** File-based routing via the `app/` directory. Each page and sub-page maps to its own route segment (e.g., `app/risk-management/qrm-platform/page.tsx`)
- **Sub-navigation:** Implement as a shared layout component (`layout.tsx`) within each section folder, so the side nav persists across sub-pages without re-mounting
- **Static vs Dynamic:** All pages are statically generated (`generateStaticParams` where needed) except `/news`, which should support ISR (Incremental Static Regeneration) with a `revalidate` interval for future CMS integration
- **Components:** Build a shared `components/` directory for reusable elements: `Navbar`, `Footer`, `SubNav`, `ServiceCard`, `TeamCard`, `NewsCard`, `ContactForm`
- **Fonts:** Use `next/font` to load the chosen typeface (e.g., Inter) with zero layout shift
- **Images:** Use `next/image` for all images with proper `width`, `height`, and `alt` attributes
- **Metadata:** Define `metadata` exports on every `page.tsx` for SEO (title, description, Open Graph)
